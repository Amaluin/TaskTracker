После применения миграции выполните в SQL Editor:

-- Проверка 1: Тип колонки изменен
SELECT column_name, data_type 
FROM information_schema.columns 
WHERE table_name = 'tasks' AND column_name = 'user_id';
-- Должно быть: uuid

-- Проверка 2: Профили созданы
SELECT COUNT(*) as users FROM auth.users;
SELECT COUNT(*) as profiles FROM public.user_profiles;
-- Числа должны совпадать

-- Проверка 3: Внешние ключи на месте
SELECT constraint_name 
FROM information_schema.table_constraints 
WHERE table_name = 'tasks' 
  AND constraint_type = 'FOREIGN KEY';
-- Должен быть: tasks_user_id_fkey

-- Проверка 4: Представления пересозданы
SELECT table_name 
FROM information_schema.views 
WHERE table_schema = 'public';
-- Должны быть: tasks_with_reminder_count, 
--               overdue_tasks, upcoming_tasks

⚠️  СУЩЕСТВУЮЩИЕ ЗАДАЧИ:
    Если у вас есть задачи с TEXT user_id, они будут удалены
    при миграции, так как старый формат несовместим с UUID.

⚠️  РЕЗЕРВНАЯ КОПИЯ:
    Рекомендуется сделать backup БД перед миграцией:
    Supabase Studio → Database → Backups

⚠️  ТЕСТИРОВАНИЕ:
    После миграции обязательно протестируйте все функции:
    - Регистрация
    - Вход
    - Создание задач
    - Изоляция данных

⚠️  PRODUCTION:
    Если это production база, выполните миграцию в нерабочее
    время и предупредите пользователей о возможном downtime.
