# Realtime обновления задач

## Проблема

При изменении статуса задачи (например, перетаскивании в Kanban) задача пропадает и не появляется в новой колонке, пока не обновишь страницу.

## Причина

Приложение не подписано на realtime обновления из Supabase. Изменения в базе данных не отображаются автоматически.

## Решение

### 1. Включить Realtime в Supabase

Выполните SQL скрипт `ВКЛЮЧИТЬ_REALTIME.sql` в вашей базе данных:

```bash
# Через psql
psql -h localhost -U postgres -d postgres -f ВКЛЮЧИТЬ_REALTIME.sql

# Или через Supabase Studio
# 1. Откройте https://studio.bike53.ru
# 2. Перейдите в SQL Editor
# 3. Скопируйте содержимое файла ВКЛЮЧИТЬ_REALTIME.sql
# 4. Нажмите "Run"
```

Или выполните команду напрямую:

```sql
ALTER PUBLICATION supabase_realtime ADD TABLE tasks;
```

### 2. Код уже обновлен

В `lib/providers/task_providers.dart` добавлена realtime подписка:

```dart
void _setupRealtimeSubscription() {
  final supabase = Supabase.instance.client;
  
  _subscription = supabase
      .channel('tasks_changes')
      .onPostgresChanges(
        event: PostgresChangeEvent.all,
        schema: 'public',
        table: 'tasks',
        callback: (payload) {
          print('🔄 Realtime event: ${payload.eventType}');
          // Перезагружаем задачи при любом изменении
          loadTasks();
        },
      )
      .subscribe();
}
```

### 3. Перезапустите приложение

```bash
flutter run
```

## Как это работает

### События Realtime

Приложение подписывается на все изменения в таблице `tasks`:

1. **INSERT** - создание новой задачи
   - Задача автоматически появляется у всех пользователей

2. **UPDATE** - обновление задачи (включая изменение статуса)
   - Задача перемещается в нужную колонку
   - Изменения видны всем пользователям мгновенно

3. **DELETE** - удаление задачи
   - Задача исчезает у всех пользователей

### Логирование

В консоли Flutter вы увидите:

```
✅ Realtime subscription установлена
🔄 Realtime event: UPDATE
   New data: {id: xxx, status: accepted, ...}
   Old data: {id: xxx, status: pending, ...}
```

### Автоматическая перезагрузка

При получении события realtime:
- Вызывается `loadTasks()`
- Обновляется состояние провайдера
- UI автоматически перерисовывается
- Задачи появляются в правильных колонках

## Отладка

### Если realtime не работает:

#### 1. Проверьте, что таблица добавлена в публикацию:

```sql
SELECT * FROM pg_publication_tables WHERE tablename = 'tasks';
```

Должна быть строка с `pubname = 'supabase_realtime'`

#### 2. Проверьте подключение в консоли:

```
✅ Realtime subscription установлена
```

Если нет - проверьте интернет соединение и URL Supabase

#### 3. Проверьте права доступа:

```sql
SELECT * FROM information_schema.table_privileges 
WHERE table_name = 'tasks' AND grantee = 'authenticated';
```

Должны быть права SELECT, INSERT, UPDATE, DELETE

#### 4. Проверьте RLS политики:

```sql
SELECT * FROM pg_policies WHERE tablename = 'tasks';
```

Политики должны разрешать SELECT для authenticated пользователей

### Если задачи дублируются:

Это может происходить, если:
- Несколько подписок на один канал
- Не отключается подписка при dispose

Решение уже реализовано:
```dart
@override
void dispose() {
  _subscription?.unsubscribe();
  super.dispose();
}
```

## Альтернативные подходы

### 1. Polling (опрос сервера)

Вместо realtime можно периодически опрашивать сервер:

```dart
Timer.periodic(Duration(seconds: 5), (timer) {
  loadTasks();
});
```

**Минусы:**
- ❌ Задержка до 5 секунд
- ❌ Лишние запросы к серверу
- ❌ Расход батареи

### 2. Optimistic updates

Обновлять UI сразу, не дожидаясь ответа сервера:

```dart
// Сразу обновляем UI
state = AsyncValue.data(updatedTasks);
// Потом отправляем на сервер
await _repository.changeStatus(taskId, newStatus);
```

**Минусы:**
- ❌ Может быть рассинхронизация
- ❌ Нужно откатывать при ошибке
- ❌ Не работает для других пользователей

### 3. Realtime (текущее решение) ✅

**Плюсы:**
- ✅ Мгновенные обновления
- ✅ Работает для всех пользователей
- ✅ Нет лишних запросов
- ✅ Всегда актуальные данные

## Производительность

### Оптимизация

Realtime подписка оптимизирована:

1. **Одна подписка на все задачи**
   - Не создается отдельная подписка для каждой задачи
   - Один канал для всей таблицы

2. **Автоматическое отключение**
   - Подписка отключается при dispose
   - Нет утечек памяти

3. **Умная перезагрузка**
   - Загружаются только измененные данные
   - Используется кеш Riverpod

### Сетевой трафик

- **WebSocket соединение**: ~1-2 KB/сек в idle
- **При изменении**: ~0.5-2 KB на событие
- **Общий трафик**: минимальный

## Дополнительные возможности

### Фильтрация событий

Можно подписаться только на определенные события:

```dart
// Только обновления
.onPostgresChanges(
  event: PostgresChangeEvent.update,
  ...
)

// Только для определенного пользователя
.onPostgresChanges(
  event: PostgresChangeEvent.all,
  filter: PostgresChangeFilter(
    type: PostgresChangeFilterType.eq,
    column: 'user_id',
    value: currentUserId,
  ),
  ...
)
```

### Множественные подписки

Можно создать отдельные каналы для разных целей:

```dart
// Канал для задач
supabase.channel('tasks_changes')...

// Канал для напоминаний
supabase.channel('reminders_changes')...

// Канал для комментариев
supabase.channel('comments_changes')...
```
