# Исправление ошибки при снятом ответственном

## Проблема

При снятии ответственного с задачи на главной странице возникала ошибка в дропдауне.

## Причина

Когда ответственный снимается, `assignedToUserId` устанавливается в пустую строку `''`. 
Дропдаун пытается найти это значение в списке items, но там есть только:
- `null` (для "Не назначен")
- ID пользователей (непустые строки)

Результат: ошибка "value not found in items"

## Решение

Преобразовать пустую строку в `null` перед передачей в дропдаун.

### Код

**Было:**
```dart
DropdownButton<String?>(
  value: widget.task.assignedToUserId, // может быть ''
  items: [
    DropdownMenuItem(value: null, child: Text('Не назначен')),
    ...users.map((user) => DropdownMenuItem(value: user.id, ...)),
  ],
)
```

**Стало:**
```dart
// Преобразуем пустую строку в null для дропдауна
final assignedUserId = widget.task.assignedToUserId?.isEmpty ?? true
    ? null
    : widget.task.assignedToUserId;

DropdownButton<String?>(
  value: assignedUserId, // всегда null или непустая строка
  items: [
    DropdownMenuItem(value: null, child: Text('Не назначен')),
    ...users.map((user) => DropdownMenuItem(value: user.id, ...)),
  ],
)
```

## Логика преобразования

```dart
final assignedUserId = widget.task.assignedToUserId?.isEmpty ?? true
    ? null
    : widget.task.assignedToUserId;
```

### Разбор:

1. `widget.task.assignedToUserId?.isEmpty` - проверяем, пустая ли строка
2. `?? true` - если assignedToUserId == null, считаем что пустая
3. `? null : widget.task.assignedToUserId` - если пустая, возвращаем null, иначе сам ID

### Примеры:

| assignedToUserId | isEmpty | ?? true | Результат |
|------------------|---------|---------|-----------|
| `null`           | `null`  | `true`  | `null`    |
| `''`             | `true`  | `true`  | `null`    |
| `'user-id-123'`  | `false` | `false` | `'user-id-123'` |

## Файлы изменены

### lib/screens/tasks/task_detail_screen.dart

**Добавлено:**
```dart
// Преобразуем пустую строку в null для дропдауна
final assignedUserId = widget.task.assignedToUserId?.isEmpty ?? true
    ? null
    : widget.task.assignedToUserId;
```

**Изменено:**
```dart
DropdownButton<String?>(
  value: assignedUserId, // вместо widget.task.assignedToUserId
  // ...
)
```

## Тестирование

### Сценарий 1: Задача без ответственного
1. Создайте задачу без ответственного
2. `assignedToUserId = ''`
3. Откройте детали задачи
4. Дропдаун должен показывать "Не назначен"
5. ✅ Нет ошибки

### Сценарий 2: Снятие ответственного
1. Создайте задачу с ответственным
2. `assignedToUserId = 'user-id-123'`
3. Откройте детали задачи
4. Выберите "Не назначен"
5. `assignedToUserId = ''`
6. Дропдаун должен показывать "Не назначен"
7. ✅ Нет ошибки

### Сценарий 3: Назначение ответственного
1. Откройте задачу без ответственного
2. Дропдаун показывает "Не назначен"
3. Выберите пользователя
4. `assignedToUserId = 'user-id-123'`
5. Дропдаун должен показывать выбранного пользователя
6. ✅ Работает корректно

## Альтернативные решения

### Вариант 1: Хранить null вместо пустой строки

**В базе данных:**
```sql
ALTER TABLE tasks 
ALTER COLUMN assigned_to_user_id DROP NOT NULL;
```

**В коде:**
```dart
final updatedTask = widget.task.copyWith(
  assignedToUserId: newUserId, // null вместо ''
  assignedToUserName: userName,
);
```

**Плюсы:**
- ✅ Более семантично (null = нет значения)
- ✅ Не нужно преобразование

**Минусы:**
- ❌ Нужно менять схему БД
- ❌ Нужно обновлять все места, где используется assignedToUserId

### Вариант 2: Добавить пустую строку в items

```dart
items: [
  DropdownMenuItem(value: null, child: Text('Не назначен')),
  DropdownMenuItem(value: '', child: Text('Не назначен')), // дубликат
  ...users.map(...),
]
```

**Плюсы:**
- ✅ Минимальные изменения

**Минусы:**
- ❌ Дублирование опции "Не назначен"
- ❌ Запутанная логика

### Вариант 3: Текущее решение (выбрано) ✅

**Плюсы:**
- ✅ Не нужно менять БД
- ✅ Не нужно менять другой код
- ✅ Простое и понятное преобразование
- ✅ Работает с существующими данными

**Минусы:**
- ⚠️ Нужно помнить о преобразовании в каждом дропдауне

## Заключение

Проблема решена добавлением простого преобразования пустой строки в `null` перед передачей в дропдаун. Это минимальное изменение, которое не требует изменения схемы БД или рефакторинга всего кода.

**Результат:**
- ✅ Нет ошибки при снятом ответственном
- ✅ Дропдаун работает корректно
