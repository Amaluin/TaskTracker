БЕЗОПАСНОСТЬ БАЗЫ ДАННЫХ - КРАТКАЯ СПРАВКА
============================================

⚠️ ТЕКУЩАЯ СИТУАЦИЯ
-------------------
Ваши RLS политики СЛИШКОМ ОТКРЫТЫЕ!

Проблема:
- Любой с Anon Key может читать/изменять/удалять ВСЕ данные
- Нет изоляции между пользователями
- Опасно для production!

Почему так:
- Приложение не использует Supabase Auth
- user_id управляется на стороне клиента
- Фильтрация данных происходит в Flutter, а не в БД

============================================
РЕШЕНИЯ (выберите одно)
============================================

ВАРИАНТ 1: Базовая защита (5 минут)
------------------------------------
✓ Быстро применяется
✓ Не требует изменений в Flutter
✗ Средний уровень защиты

Применение:
1. Откройте: https://studio.bike53.ru
2. SQL Editor → New query
3. Скопируйте database_security.sql
4. Вставьте и нажмите Run

Уровень защиты: 🟡 Средний
Для: Разработка, тестирование

---

ВАРИАНТ 2: API ключи (рекомендуется)
-------------------------------------
✓ Высокая безопасность
✓ Изоляция данных пользователей
✗ Требует изменений в Flutter

Применение:
1. В database_security.sql раскомментируйте ВАРИАНТ 2
2. Выполните в SQL Editor
3. Обновите Flutter:

// Добавьте API ключ в заголовки
final response = await supabase
  .from('tasks')
  .select()
  .headers({'x-api-key': userApiKey});

Уровень защиты: 🟢 Высокий
Для: Production

---

ВАРИАНТ 3: Supabase Auth (максимум)
------------------------------------
✓ Максимальная безопасность
✓ Встроенная аутентификация
✗ Требует переработки приложения

Применение:
1. В database_security.sql раскомментируйте ВАРИАНТ 3
2. Выполните в SQL Editor
3. Переработайте аутентификацию в Flutter:

// Регистрация
await supabase.auth.signUp(
  email: email,
  password: password,
);

// Вход
await supabase.auth.signInWithPassword(
  email: email,
  password: password,
);

Уровень защиты: 🟢🟢 Максимальный
Для: Production (лучшая практика)

============================================
БЫСТРОЕ РЕШЕНИЕ (прямо сейчас)
============================================

Если нужно быстро:

1. Откройте Studio: https://studio.bike53.ru
2. SQL Editor → New query
3. Скопируйте и выполните:

-- Базовая защита
DROP POLICY IF EXISTS "Enable all operations for tasks" ON tasks;

CREATE POLICY "Allow anon operations on tasks"
  ON tasks FOR ALL
  TO anon
  USING (true)
  WITH CHECK (true);

4. Повторите для task_reminders и task_status_history

Это не идеально, но лучше чем сейчас!

============================================
ДОПОЛНИТЕЛЬНЫЕ МЕРЫ
============================================

1. Ограничьте доступ к Studio по IP
   nginx-supabase.conf → allow YOUR_IP; deny all;

2. Не публикуйте Anon Key в открытом виде

3. Включите rate limiting
   См. database_security.sql

4. Настройте аудит логирование
   См. database_security.sql

5. Регулярно обновляйте Anon Key
