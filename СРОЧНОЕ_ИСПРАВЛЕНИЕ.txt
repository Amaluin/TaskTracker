ОШИБКА:
  insert or update on table "tasks" violates 
  foreign key constraint "tasks_user_id_fkey"
  Key (user_id)=(bbea4612-574b-433f-bc10-9a227c74d780) 
  is not present in table "users"

ПРИЧИНА:
  Внешний ключ ссылается на неправильную таблицу!
  
  ❌ Сейчас: tasks.user_id → public.users (не существует)
  ✅ Нужно:  tasks.user_id → auth.users (существует)

═══════════════════════════════════════════════════════════
РУЧНОЕ ИСПРАВЛЕНИЕ (если скрипт не помог)
═══════════════════════════════════════════════════════════

Выполните в SQL Editor:

-- Шаг 1: Удалить неправильный ключ
ALTER TABLE tasks 
DROP CONSTRAINT IF EXISTS tasks_user_id_fkey;

-- Шаг 2: Создать правильный ключ
ALTER TABLE tasks 
ADD CONSTRAINT tasks_user_id_fkey 
FOREIGN KEY (user_id) 
REFERENCES auth.users(id) 
ON DELETE CASCADE
DEFERRABLE INITIALLY DEFERRED;

-- Шаг 3: Проверить
SELECT
  tc.constraint_name,
  ccu.table_schema || '.' || ccu.table_name AS references
FROM information_schema.table_constraints AS tc
JOIN information_schema.key_column_usage AS kcu
  ON tc.constraint_name = kcu.constraint_name
JOIN information_schema.constraint_column_usage AS ccu
  ON ccu.constraint_name = tc.constraint_name
WHERE tc.table_name = 'tasks'
  AND kcu.column_name = 'user_id';

-- Должно показать: auth.users

ПРОВЕРКА ПОСЛЕ ИСПРАВЛЕНИЯ
═══════════════════════════════════════════════════════════

1. Внешний ключ ссылается на auth.users:
   
   SELECT
     ccu.table_schema || '.' || ccu.table_name
   FROM information_schema.table_constraints AS tc
   JOIN information_schema.constraint_column_usage AS ccu
     ON ccu.constraint_name = tc.constraint_name
   WHERE tc.table_name = 'tasks'
     AND tc.constraint_name = 'tasks_user_id_fkey';
   
   Ожидается: auth.users

2. Пользователь существует:
   
   SELECT id, email 
   FROM auth.users 
   WHERE id = 'bbea4612-574b-433f-bc10-9a227c74d780';
   
   Ожидается: 1 строка

3. Профиль существует:
   
   SELECT * 
   FROM public.user_profiles 
   WHERE id = 'bbea4612-574b-433f-bc10-9a227c74d780';
   
   Ожидается: 1 строка

═══════════════════════════════════════════════════════════
ПОЧЕМУ ЭТО ПРОИЗОШЛО?
═══════════════════════════════════════════════════════════

Возможные причины:

1. Миграция database_auth_migration.sql не была применена
   полностью или была прервана

2. Внешний ключ был создан вручную с неправильной ссылкой

3. Существует старая таблица public.users, которая
   конфликтует с auth.users

4. PostgreSQL неправильно интерпретировал схему при
   создании внешнего ключа

═══════════════════════════════════════════════════════════
ПРЕВЕНТИВНЫЕ МЕРЫ
═══════════════════════════════════════════════════════════

Чтобы избежать этой проблемы в будущем:

1. Всегда указывайте схему явно:
   REFERENCES auth.users(id)
   а не просто REFERENCES users(id)

2. Проверяйте внешние ключи после миграции:
   SELECT * FROM information_schema.table_constraints
   WHERE table_name = 'tasks';

3. Используйте DEFERRABLE для внешних ключей,
   связанных с auth.users
