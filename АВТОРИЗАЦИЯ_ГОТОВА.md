## 🚀 Следующие шаги

### Шаг 1: Применить миграцию БД

1. Откройте Supabase Studio: **https://studio.bike53.ru**
2. Перейдите в **SQL Editor**
3. Нажмите **New query**
4. Скопируйте содержимое файла `database_auth_migration.sql`
5. Вставьте в редактор и нажмите **Run**

⚠️ **ВАЖНО**: Если у вас есть существующие задачи, они будут удалены при миграции, так как старые TEXT user_id несовместимы с новыми UUID. Если нужно сохранить данные, сначала создайте пользователей через регистрацию, затем вручную обновите user_id в задачах.

### Шаг 2: Настроить Supabase Auth

1. В Supabase Studio перейдите в **Authentication** → **Settings**
2. Убедитесь, что включено:
   - ✅ Enable email confirmations: **OFF** (для упрощения разработки)
   - ✅ Enable email signup: **ON**
3. В разделе **Email Templates** можно настроить письма (опционально)

## 📋 Как это работает

### Архитектура авторизации

```
Пользователь вводит телефон
         ↓
+79001234567 → 79001234567@tasktracker.local
         ↓
    Supabase Auth
         ↓
    JWT токен (автоматически)
         ↓
    auth.uid() в запросах
         ↓
RLS политики фильтруют данные
         ↓
Пользователь видит только свои задачи
```

### Безопасность

1. **Пароли**: Хешируются Supabase (bcrypt)
2. **Токены**: JWT с автоматическим обновлением
3. **RLS**: Каждый пользователь видит только свои данные
4. **Внешние ключи**: Защита целостности данных

### Формат телефона

- **Ввод**: `9001234567` или `89001234567` или `+79001234567`
- **Нормализация**: `+79001234567`
- **Email для Auth**: `79001234567@tasktracker.local`
- **Хранение в профиле**: `+79001234567`

## 🔧 Возможные проблемы

### Ошибка: "User not authenticated"
**Решение**: Пользователь не авторизован. Выйдите и войдите снова.

### Ошибка: "Invalid login credentials"
**Решение**: Неверный телефон или пароль. Проверьте данные.

### Ошибка: "User already registered"
**Решение**: Пользователь с таким телефоном уже существует. Используйте вход.

### Задачи не создаются
**Решение**: 
1. Проверьте, что миграция БД применена
2. Проверьте, что пользователь авторизован
3. Проверьте логи в Supabase Studio → Logs

### Не видно задач после входа
**Решение**:
1. Проверьте RLS политики в Supabase Studio
2. Убедитесь, что `user_id` в задачах соответствует `auth.uid()`
