ТЕХНИЧЕСКОЕ ЗАДАНИЕ
на разработку мобильного приложения «Task Tracker»


1. ВВЕДЕНИЕ

Настоящее техническое задание определяет требования к разработке мобильного приложения «Task Tracker» — системы управления задачами с возможностью назначения ответственных, отложения задач и напоминаний.

Приложение предназначено для управления личными и рабочими задачами с использованием методологии Kanban. Пользователи могут создавать задачи, назначать ответственных, откладывать выполнение и получать уведомления о напоминаниях.

Целевая аудитория — индивидуальные пользователи для личной организации задач и небольшие команды для совместной работы над задачами.


2. ОБЩЕЕ ОПИСАНИЕ

Приложение работает на мобильных платформах iOS и Android. Предусмотрен адаптивный интерфейс для web-браузеров при ширине экрана более 900 пикселей.


3. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

3.1. Управление задачами

Пользователь может создать новую задачу, указав название (обязательное поле), описание по желанию, приоритет (низкий, средний, высокий) и срок выполнения в виде даты и времени. При создании задаче автоматически присваивается статус «В ожидании». Каждая задача привязывается к идентификатору пользователя.

Пользователь может изменить название, описание, приоритет и срок выполнения задачи. Все изменения сохраняются в базе данных с обновлением поля updated_at.

Задачу можно удалить. При удалении задачи все связанные с ней напоминания удаляются автоматически.

Приложение поддерживает четыре статуса задач:

- В ожидании — задача создана, но не начата (значение в базе: pending);
- В работе — задача принята и выполняется (значение в базе: accepted);
- Отложено — задача отложена на определённое время (значение в базе: postponed);
- В архиве — задача завершена и архивирована (значение в базе: archived).

3.2. Назначение ответственного

В карточке задачи отображается раздел «Ответственный». Пользователь может назначить другого пользователя ответственным за задачу, при этом сохраняются его идентификатор и имя. Ответственного можно снять с задачи. Имя ответственного отображается как в карточке задачи, так и в общем списке задач.

Если задача назначена на пользователя, в карточке появляется кнопка «Принять задачу». При нажатии на неё статус автоматически меняется на «В работе», создаётся напоминание за один час до срока выполнения (если срок установлен) и отправляется уведомление о создании напоминания.

3.3. Отложение задачи

Любую задачу можно отложить с помощью кнопки «Отложить задачу». Открывается диалог выбора даты и времени: календарь на русском языке и выбор времени в стиле iOS (барабан с часами и минутами). При подтверждении статус задачи меняется на «Отложено», дата и время сохраняются в поле postponed_until, и автоматически создаётся напоминание на выбранное время. Дата отложения отображается в карточке задачи.

3.4. Напоминания

Пользователь может создать напоминание для любой задачи. Напоминание содержит идентификатор задачи, идентификатор пользователя, время срабатывания, тип (уведомление или будильник) и флаг включения. Пользователь может просмотреть список напоминаний, удалить ненужные. При удалении задачи все связанные напоминания удаляются автоматически.

Система отправляет локальные уведомления в соответствии с настроенными напоминаниями. Уведомления работают на iOS и Android.

3.5. Просмотр задач

На мобильных устройствах (ширина экрана до 900 пикселей) задачи отображаются в виде списка карточек. Каждая карточка содержит название задачи, приоритет с цветовой индикацией, срок выполнения, имя ответственного (если назначен), дату отложения (если применимо) и текущий статус.

На устройствах с шириной экрана более 900 пикселей отображается Kanban-доска с четырьмя колонками по статусам задач: «В ожидании» (янтарный цвет), «В работе» (синий цвет), «Отложено» (фиолетовый цвет), «В архиве» (серый цвет). Реализован механизм Drag & Drop для перемещения задач между колонками — перемещение автоматически обновляет статус задачи.

3.6. Пользовательский интерфейс

Приложение использует стиль Glassmorphism: полупрозрачные карточки с эффектом размытия, скруглённые углы, современный минималистичный дизайн. Основной цвет приложения — индиго-фиолетовый. Интерфейс адаптирован для мобильных и web-устройств.

Весь интерфейс переведён на русский язык, календарь отображается на русском, даты и время форматируются согласно русской локали.

3.7. Экран входа

При первом запуске пользователю предлагается ввести своё имя. Имя сохраняется локально и используется для идентификации. При последующих запусках приложение автоматически использует сохранённое имя.


4. НЕФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

Время отклика интерфейса при выполнении операций не должно превышать 200 миллисекунд. Приложение должно корректно обрабатывать состояние загрузки данных.

При ошибках сети приложение отображает соответствующее сообщение пользователю. Данные сохраняются в базе данных Supabase после каждого изменения.

Приложение должно поддерживать iOS версии 12.0 и выше, а также Android API уровня 21 и выше.
